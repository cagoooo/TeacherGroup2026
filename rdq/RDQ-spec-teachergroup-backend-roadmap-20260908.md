# RDQ 需求規格：TeacherGroup2026 後端後續改良

## 一句話任務
在現有匿名 GAS＋Google Sheets 統計穩定運作後，規劃下一階段後端維運、報表、權限與會員資料功能的可選開發路線。

## 已確認
- 會長於本對話選定 `BACKEND-01`、`BACKEND-02`、`BACKEND-03`、`BACKEND-04`，授權進入實作；`BACKEND-05` 未選。
- 現行網站為 GitHub Pages 靜態網站，公開版本為 **2026.09.08-4**。
- 現行後端為 GAS Web App＋私人 Google 試算表，每日彙總固定事件，不儲存原始訪客紀錄。
- 現行統計不收集姓名、電話、電子郵件、會員名冊、付款資料、IP 或 User-Agent；事件次數不等同於去重後的教師人數。
- 校內分工仍是教師小組代收、財務長處理工會匯款、支會長協助新進／中斷會員建檔。
- 後續規劃須維持石門國小校內流程，不得把匿名統計誤用為會員名冊或繳費對帳資料。

## 待確認假設
- 本次實作預設：初始只有部署者具擁有者權限；同學校網域管理者由擁有者自行加入。擁有者／維運者／檢視者為技術權限，不自動推定校內職稱。
- 保存政策預設統計與稽核 365 天、備份 30 天，皆為到期檢視提醒，不自動刪除；可由擁有者調整。
- 每日 03 時（台灣時區）附近執行備份；復原演練只建立獨立私人試算表。
- 匿名端點全站上限暫設每分鐘 120、每日 20,000 次；單事件隨機請求碼僅快取 10 分鐘，協助短期去重，不識別老師。
- 管理稽核需要記錄管理者 Google 帳號，存於私人稽核表；匿名訪客事件仍不記錄身分。
- 使用對象 → 預設先服務石門國小管理者，不立即開放全工會管理權限。
- 報表範圍 → 預設先做匿名事件趨勢與 CSV／JSON 匯出，不做教師身分辨識。
- 儲存與部署 → 預設沿用學校管理帳號的 GAS＋Google Sheets；若改用資料庫，需另立安全與成本評估。
- 會員資料後台 → 預設獨立於匿名統計，待角色權限、保存期限、備份與個資告知確認後才開發。

## 待會長回答的 RDQ 訪談題
1. 第一階段主要使用者：A 僅會長／財務長／支會長；B 教師小組也可看報表；C 全工會管理者；D 不確定／其他。
2. 匿名統計保存方式：A 只保留每日彙總；B 保留一年並可匯出；C 長期保存但每年封存；D 不確定／其他。
3. 是否進入會員個資後台：A 暫不做；B 只做登入後的名冊／收款管理；C 連同通知與對帳流程一起規劃；D 不確定／其他。
4. 管理介面優先順序：A 先做健康檢查與備份；B 先做圖表與報表；C 先做權限與稽核；D 不確定／其他。

## 象限Ⅳ建議選單
- `BACKEND-01` 維運健康、備份、保存期限與復原演練 — 工時低至中，可降低試算表遺失與部署中斷風險。
- `BACKEND-02` 私人匿名報表頁與 CSV／JSON 匯出 — 工時中，可快速看區塊趨勢，但仍不是教師人數。
- `BACKEND-03` 端點反灌量、事件版本治理與失敗監測 — 工時中，可提高匿名端點可信度，但無法在完全匿名下保證一人一次。
- `BACKEND-04` 管理者登入、角色權限與操作稽核 — 工時中至高，可限制報表與設定存取，需處理帳號異動。
- `BACKEND-05` 會員名冊、收款與對帳後台 — 工時高、個資風險高，需另訂欄位、權限、保存期限與測試資料政策。

## 本次不納入
- 本輪不修改現行收費金額、校內代收流程或財務長／支會長分工。
- 未確認前不建立會員個資資料表、不匯入真實名冊、不開放公開登入或付款功能。
- 不把匿名事件數直接標示為「使用老師人數」，也不以公開匿名端點作為正式會員資格證明。

## 一段式需求規格
請以 **TeacherGroup2026** 公開版本 **2026.09.08-4**、現有 GAS Web App＋私人 Google 試算表匿名彙總後端、石門國小教師小組代收／財務長匯款／支會長建檔分工為基礎，先完成後端後續優化的選項、風險、成本、權限與驗收規劃；優先評估維運健康、備份保存、匿名報表、端點治理、管理者權限及會員個資後台等路線，任何涉及姓名、聯絡方式、會員名冊或收款紀錄的功能，須在角色矩陣、個資告知、保存期限、備份與測試資料方案確認後才可開發。
